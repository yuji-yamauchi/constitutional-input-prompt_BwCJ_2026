## 0. これは何か

> **本人だけが開ける、一つのアプリです。**

働きは三つ、そしてその先に「人に渡す口」が一つあります。

| | 働き | 要点 |
|---|---|---|
| **1** | **書く練習** | 本人が自分の言葉で書く。書き方の条件（一度に書く量・区切り方・言葉のやさしさ・入力の形）は**本人が選ぶ**。Claude は問いを返し、**本人の文を一字も変えずに読み返すだけ**。書きかえ・要約・採点・助言をしない |
| **2** | **自分の記録の引き出し** | 他の人が自分について書いた記録（診断書・計画・通知表）を、本人が写真で入れる。**写真は原本のまま**で、読み取った文字には「**写し**」の札が付く。「誰が・いつ・どの手続きで書いたか」が添えられ、本人は**注記や異議を別の行として**付けられる。**原本は変わらない** |
| **3** | **今の困りごとの整理** | 本人の言葉で並べる。法令は**あらかじめ原文から写した閉じた集合からだけ**、出典つきで出す。**その条文が自分に当てはまるかを、このアプリは言わない** |
| **＋** | **人に渡す口** | 本人が選び「わたす」を押したときだけ、**写し**が外に出る。受け取った側は**控え**を返し、控えは本人の手元に残る |

**このアプリは、本人を判定しません。** 点も、順位も、段階も、状態の評価も出しません。
**数えるのは、本人が選んだ「条件」であって、本人ではありません。**

## 3. データの形

### 本人の箱

- 本人の合言葉（環境変数 `VAULT_PASSPHRASE`）で開く。**画面に設定の欄は無い**
- 原本（写真）と、読み取った文字（写し）は**別物として持つ**
- 記録には **`sha256` の指紋**が付き、**一字 変われば指紋が変わる**
- 注記・異議は**別の行**として足す。**原本は変わらない**
- 一日の記録＝就寝・起床・朝食・きょうの気分

### 渡すときの契約

- **写しだけが出る。原本は出ない**
- **件数・指紋・「誰が書いたか」の札**が束に付く
- 受け取った側は**控え**を返し、**控えは本人の手元に残る**
- **受け口は Claude を一度も呼ばない**（検査と門の両方で見ている）

### 法令集

- **1 条 = 1 つの JSON。** 欄＝`id` `law_name` `article` `text_verbatim` `source_name` `retrieved_on` `retrieved_by` `set_version` `verified_by_person` `note`
- **`verified_by_person` が `true` の条だけ**が画面に出る
- **`true` にする人＝作成者**（人が原文と読み合わせる）。欄が欠けた物・読めない物・`_` で始まる物・`id` が重複する物は**読まない**
- 現在＝**7 条とも `true`**。原文との突合の結果は [`08_sources/`](../../08_sources/) にあります

## 6. 今回つくらなかった物

> **小さいデモより、違う物に見えるデモのほうが悪い。**

| | 今回 |
|---|---|
| 本人の画面（書く・今日の欄・印・わたす） | **本物。動く** |
| 60 問の問い | **本物。ファイルから動く。データベースは使っていない** |
| 会話の返事 | **あらかじめ用意した物**。**画面にもそう出す**。設計は API で Claude につなぐ形 |
| **過去の記録を AI が分析すること** | **無い。意図して置いていない。**（自分の過去を、他に誰も居ない所で AI に読み返されること——この設計が唯一ことわっているのが、そこ） |
| 記録の写真の保存／支援者へ育成の記録を渡すこと | **モックアップだけ**。セキュリティの設計が終わっていないので、**本物は何も保存しない** |

全体像は**九つの枠**です（縦＝過去・現在・未来／横＝本人のみ・本人＋AI・本人＋AI＋支援者）。
**今回つくったのは「現在 × 本人のみ」の一枠**と、その受け口。
**「過去 × 本人＋AI」の枠は、存在させない**と決めています。

## 6-2. 測るのは、三人そろったときだけ

| その場に居るのは | できること |
|---|---|
| **本人だけ** | **記録だけ。測りません。** |
| **本人と AI** | **記録だけ。測りません。** |
| **本人と AI と支援者** | **本人がそう決めたときに限り**、過去の記録を使って、**変化**や、その**速さ**を見ます |

### 九つの枠への当てはめ

| 枠 | 扱い |
|---|---|
| 本人のみ の三枠 | **記録だけ。** 変化を見る機能は開かない |
| 本人＋AI の三枠 | **記録だけ。** 変化を見る機能は開かない |
| 本人＋AI＋支援者 の三枠 | **本人の意思があるときに限り**、変化を見る機能が開く |

### 実装に効くこと

1. 問いの働きが語彙や読解を見ることになっても、**その値を本人に返さない。** 使うのは**AI 側の話し方を決めるため**だけ
2. **変化を見る機能は、支援者が居る枠でのみ開く。** 支援者が居なければ開かない。これは**鍵であって、免責ではない**
3. 「変化」を出すときも、**点・順位・段階・前回との比べ・上達の語を画面に出さない**
4. **本人の意思が先。** 器の側からも支援者の側からも開かない
5. 公開面では「成長」という語を使わず、「**変化**」「**その速さ**」と書く

### なぜそう分けるのか

同じ数字でも、**本人に返される判定**なら鏡になり、**本人が自分を描くための素材**なら自画像になります。
分かれ目は、道具ではありません。**返し方と、そのときに誰が居るか**です。

本人と AI の二人だけで閉じると、**解釈が、異議を言う相手のいないまま本人に返ります。**
人が間に入っていれば、解釈は「**違う**」と言える相手がいる状態で返ります。

だから「測る／測らない」を設定で切り替えるのではなく、**その場に誰が居るかで決まる**形にしています。

## 7. Claude をどう使ったか

### 作るとき

**Claude Code を開発の中心に据えました。** 席（別々のセッション）に分け、**ディスク上の手紙 1 通だけ**でつながる形で回しています。

| 席 | 役 |
|---|---|
| vsclaude | 割り振りと**公開の門**（提出はここを通る） |
| hacka | 実装と調べもの |
| fable | 設計（仕様 → 実装 → 検品を別の脚で） |
| vision | 理念の側からの検査 |
| bclaude | 外部調査（規約・法令・先行事例） |
| rules | 大会規約のルールブック |
| （Claude ではない席） | 同じ問いを、別の作り手のモデルへ |

**作った席は、自分の成果物の最終検査をしません。**

### 器の中で

Claude を使うのは **三つだけ**です。

1. 問いを返し、本人の文を**一字も変えずに**読み返す
2. 写真から字を読む
3. **閉じた集合からだけ**条文の候補を出す

**意図して使っていない所**＝受け口の返事（人が書く）／印と数（本人が付け、器が数える）／誰が書いたかの確認／**条文を人に当てること**／**人の状態を判定すること**。
